Advanced Document Understanding + RAG Foundation ? implementation report

Implemented September 10, 2026. This report describes this feature's changes; the workspace already contained substantial unrelated uncommitted work.

1. **Feature summary.** Uploads, pasted text, and document edits now produce persistent, ordered knowledge chunks. Document chat and Ask LifeAdmin retrieve bounded evidence. Document chat shows document names, page/chunk references, and a View source panel. Unsupported queries with no matching chunks return exactly ?I could not find this information in the document.? without calling an AI provider.

2. **Architecture changes.** Extended the existing document chunking service and reused its knowledge splitter in the existing chat context helper. The existing PDF and image OCR pipeline still extracts text before saving; indexing runs before the existing automatic AI analysis/task-generation flow. The analysis service retains its existing separate cost guards. A knowledge service handles revision publication, retrieval, lazy backfill, and source access. Existing provider routing continues to generate answers. Embedding and vector adapters introduce no dependencies or paid service requirement.

3. **Files created.** `server/src/models/DocumentChunk.js`; `server/src/services/documentKnowledgeService.js`; `server/src/services/embeddingService.js`; `server/src/services/vectorStoreService.js`; `server/src/scripts/testDocumentKnowledge.js`; `server/src/scripts/createKnowledgeFixtures.js`; `server/src/scripts/backfillDocumentKnowledge.js`; this report; `docs/document-knowledge-manual-testing.md`; and four PDFs in `docs/fixtures/document-knowledge/`.

4. **Files modified.** See the inventory below. Changes in existing uncommitted files were made in place; unrelated functionality was preserved.

5. **Database changes.** Added the `documentchunks` collection with user/document IDs, revision, chunk index, exact content, character count, offsets, optional page, section label, timestamps, and optional embedding/model fields. A compound unique index prevents duplicate chunks in a revision; a user-prefixed text index supports collection candidate search. Documents gain `knowledgeRevision` and `knowledgePending`; chat source metadata gains document ID/title, page, and revision. No destructive migration is required. Existing documents are indexed lazily, or with the scoped backfill command in the manual guide. Explicitly create indexes via that command when production disables automatic index creation.

6. **AI flow.** Authenticated request ? verify document ownership ? ensure current chunks ? expand the query with existing aliases/intent and bounded follow-up context ? rank current chunks using text relevance and optional vectors ? fit complete chunks to the context budget ? call the existing AI provider ? return an answer plus backend-selected sources. Invalid inline chunk citations are removed. Page boundaries are preserved when existing PDF markers are available. Workspace retrieval first uses MongoDB text matches, title matches, and pending/legacy documents; only five bounded document contexts are retained. It falls back to a streamed metadata scan if the text index is unavailable.

7. **Security review.** Ownership is checked before indexing and source reads. Chunk and vector queries are scoped to user, document, and revision. Search candidates are reloaded through document ownership checks. Vector hits can only rank chunks loaded from that verified scope. Source routes require authentication and the citation revision; edits return 409 for old citations and deletion returns 404. Publication checks the original extracted text and retrieval revalidates the published revision/text, preventing stale builds from becoming evidence. Prompts treat retrieved text as untrusted and prohibit secret disclosure. Optional provider errors are sanitized and fall back to text retrieval. The error middleware no longer returns raw development error details. Existing transactional deletion now includes vectors/chunks; standalone MongoDB retains the existing sequential cleanup behavior.

8. **Automated results.** All ten suites listed below passed against the local MongoDB where applicable. The new knowledge suite passed 29 checks, including a real PDF upload with 130 pages, a page 113 citation, two-user isolation, source access, edits, deletion, idempotence, indexed workspace retrieval, and embedding/vector failure fallback. AI responses were mocked; upload/PDF-only suites disabled AI providers. Existing analysis/task tests used their own mocks. Frontend production build passed, with Vite's warning about a JavaScript bundle exceeding 500 kB. No dependencies were added. A separate local chunking measurement covered 1,890,000 characters in 480 chunks in approximately 239 ms. This is a local splitter measurement, not a production latency SLA.

9. **Manual results.** Four reproducible PDF fixtures were generated. Automated HTTP tests exercised upload, extraction, source reads, chat persistence, and cleanup using those same fixture generators. Interactive browser testing and live-provider answer-quality review were not performed; follow the separate manual guide. No deployment was performed.

10. **Known limitations.** Default retrieval is lexical with aliases, not a trained semantic embedding model; paraphrases and non-English queries may miss evidence. Embedding providers are adapter interfaces only; enabling a future adapter requires implementation and reindexing. The default Mongo vector adapter scans at most 2,000 vectors per document and is a foundation, not an ANN index. Collection candidate search uses the best 200 text-hit chunks plus title/pending matches, so it is not exhaustive collection analysis. Overview answers use selected excerpts and are instructed not to claim whole-document coverage. Individual-document ranking currently loads that document's current chunks. Extraction is capped at 2,000,000 characters and uploads retain the existing 10 MB file limit. The separate automatic-analysis limit remains 90,000 characters by default; larger documents remain searchable even when automatic analysis cannot complete. Extremely long sentences must split at whitespace (or a hard boundary for oversized tokens); sentence detection is heuristic, and overlap stays within pages and available sentence boundaries. OCR remains the existing printed-English image OCR; scanned PDF OCR was not added. Single-page PDFs and non-PDF sources can use chunk references instead of page references. Source panels open extracted text, not a highlighted PDF coordinate. Legacy chat citations without revisions require asking the question again. Standalone Mongo deletion is not transactional; operational interruption can require retry/backfill and orphan maintenance. Browser usability and live LLM factuality still require review.
