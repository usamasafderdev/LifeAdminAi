AI Daily Briefing & Proactive Assistant - implementation report

Milestone 3, Feature 5. Implemented September 10, 2026. Existing unrelated workspace changes and earlier document-knowledge/personal-memory work were preserved.

1. **Feature summary.** The dashboard now includes an AI Daily Briefing card, "Your day with LifeAdmin", with Focus Today, today's reminders, Upcoming, Recommendations, recent documents, and actionable analyzed documents. It generates on dashboard access, reuses the local-day cache, and supports manual regeneration, hiding/showing, and disabling/re-enabling. Empty accounts receive "No important tasks today. Enjoy your day."

2. **Architecture changes.** A thin authenticated controller delegates to dailyBriefingService. The service streams active task records, reuses applyTaskPriority and summarizeTaskDeadlines, collects bounded reminder/document data, retrieves safe relevant memory preferences, generates validated narrative selections, and manages caching. briefingAiService uses the existing provider abstraction with an 8-second per-provider timeout. No additional dependencies, priority engine, task scheduler, or conversation system was created. Existing planning behavior remains in document/workspace chat; no separate planning/goal/milestone model exists in this workspace.

3. **Database changes.** Added DailyBriefing with userId, local date, canonical time zone, typed content, generatedAt, mode, privacyStamp, revision, generation-lease metadata, and expiresAt. A unique userId/date/timeZone index prevents duplicate daily entries. A TTL index expires snapshots after eight days, with asynchronous MongoDB cleanup. User gains briefingSettings.enabled (default true), hidden (default false), and version. Existing users receive safe defaults without a destructive migration. Production deployments with auto-indexing disabled must create the indexes declared in DailyBriefing.js using their normal migration process before rollout.

4. **Backend files created.** `server/src/models/DailyBriefing.js`, `server/src/services/dailyBriefingService.js`, `server/src/services/briefingAiService.js`, `server/src/controllers/briefingController.js`, `server/src/routes/briefingRoutes.js`, and `server/src/scripts/testDailyBriefing.js`. Modified `server/src/models/User.js`, `server/src/app.js`, and `server/package.json` to register settings, routes, and tests.

5. **Frontend changes.** Added `src/services/briefingService.js` and `src/components/DailyBriefingCard.jsx`, including the reusable settings controls. Updated `src/pages/Dashboard.jsx` to show the card near the top; `src/pages/Settings.jsx` now has a Daily briefing section; `src/styles.css` adds responsive briefing layouts. The browser supplies its IANA time zone. Task/document/reminder links use existing routes. Unmount/request guards prevent a late response from replacing a newer view. While visible, the dashboard checks the cache once a minute and on focus so an open dashboard can cross midnight; these checks do not normally call AI. The new report and manual guide live under `docs/`.

6. **AI prompt design.** The backend owns all facts, priorities, explanations, counts, and available narrative options. AI selects a summary ID and at most three recommendation IDs from that grounded set, using safe style preferences where useful. Unknown IDs, extra priority fields, malformed JSON, duplicate recommendation IDs, or invented text fail validation. Final strings are resolved from backend options; raw provider prose never enters the response. Task ordering is based on effective priority and existing engine score, with an overdue item retained for attention when necessary. High attention is separate from priority, so an overdue task with a user's low-priority override remains low priority.

7. **Caching strategy.** Cache identity is authenticated user + server-derived local date + canonical time zone. A valid entry avoids task collection, memory retrieval, and AI calls on repeated page loads. Manual POST refresh intentionally creates a new snapshot. A new local day creates a new entry. A MongoDB lease and revision compare-and-set prevent concurrent workers from generating duplicate briefings for the same snapshot. Leases expire after 60 seconds so interrupted workers can recover. Concurrent callers get the previous valid snapshot or a controlled generating state. AI failures and empty results are also cached. Briefing settings changes clear the user's cached snapshots; memory privacy-version changes invalidate personalization. Disabling while generation is running prevents late publication. This feature does not schedule emails, notifications, or task mutations.

8. **Security review.** Authentication uses the existing protect middleware. Controllers never accept a userId override; all task, reminder, document, memory, and cache operations are user-scoped. Dates are derived from server time and a validated time zone, not a client-provided calendar date. The briefing does not read document bodies or AI analysis prose. Sensitive-looking titles are excluded using the existing memory privacy validator; only safe preferences are supplied proactively, not personal memory facts. Generated content cannot change priorities or authorize actions. Raw provider errors and secret values are not returned. Cached preferences are not stored verbatim. Settings changes recheck privacy before publication. Sensitive-content recognition remains heuristic rather than a guarantee against disguised credentials.

9. **Automated tests.** `npm.cmd run test:daily-briefing` passed 33 checks using local MongoDB and mocked AI. Coverage includes tasks, overdue attention, empty accounts, ownership, same-day cache reuse, manual HTTP refresh, priority fidelity, safe preferences, sensitive-title exclusion, both DST transitions, invalid time zones, malformed/hostile AI output, fallback, concurrent generation, expired leases, new-day generation, and disabling during generation. Seven existing regression suites passed: priority engine, dashboard focus, dashboard deadlines, personal memory, document chat quality/planning modes, reminders, and dashboard/calendar integration. The production frontend build passed; Vite reports the existing warning for a JavaScript bundle larger than 500 kB. No paid/live AI call was needed for these tests.

10. **Manual testing results.** Interactive browser and live-provider testing were not performed. Automated service and HTTP tests exercised real authenticated requests and database persistence. Exact UI test steps and expected outcomes are in `daily-briefing-manual-testing.md`. No deployment or background notification setup was performed.

11. **Known limitations.** There is no active-goals or milestone model in the current application; goals/milestones are empty and goalSourceAvailable is false, rather than inventing records or adding another feature. The daily action plan is a ranked focus list and recommendations, not a time-blocked scheduling engine. Narrative choices are deliberately constrained, so arbitrary AI prose and translation are not supported by this briefing. Cache entries are daily snapshots: task completion/deletion, uploads, and new records are reflected after manual refresh or the next day, not by making new AI calls on each page refresh. Data collection streams all active tasks and retains bounded lists: five focus tasks, eight today's reminders, eight upcoming items, five recent documents, and five important documents. Reminder/document queries have bounded candidate windows, so this is not an exhaustive history view. Upcoming means the next 14 calendar days. Sensitive-title filtering can omit benign titles or miss unusual/encoded secrets; counts reflect eligible records. Memory privacy changes invalidate the next briefing request but cannot retract context already sent to a provider. The application needs a working database for collection/cache operations; AI fallback does not solve a database outage. Browser usability and live AI selection quality still need manual review.

| Endpoint                                   | Behavior                                                               |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| `GET /api/briefings?timeZone=Asia/Karachi` | Return or generate the authenticated user's local-day briefing         |
| `POST /api/briefings/refresh`              | Generate a new snapshot; accepts only `{ "timeZone": "Asia/Karachi" }` |
| `GET /api/briefings/settings`              | Read enabled/hidden settings without generating                        |
| `PATCH /api/briefings/settings`            | Update boolean enabled/hidden settings; invalidate snapshots           |

Response includes enabled, hidden, briefing, cached, generatedAt, timeZone, and mode where applicable. The mode is ai, fallback, or empty. Concurrent generation may return generating=true and briefing=null; changed settings may return settingsChanged=true. Internal user IDs, cache leases, privacy stamps, and provider diagnostics are not part of the public response.
